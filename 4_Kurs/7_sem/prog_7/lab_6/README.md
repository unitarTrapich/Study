# Лабораторная работа №6
### практика OAuth 2.0 в Python

## Цель работы  
Познакомиться с концепциями OAuth 2.0, реализовать поток Authorization Code в Python, получить и использовать access token для доступа к защищённому ресурсу, а также изучить возможности обновления токенов.

## Выполненные задания  

### Задание 1: Реализация Authorization Code Flow  
1. Установлено окружение: Python 3.11+, создано виртуальное окружение, установлены библиотеки `requests` и `requests-oauthlib`.  
2. Зарегистрировано OAuth-приложение на GitHub, получены `client_id` и `client_secret`, указан `redirect_uri`.  
3. Написан скрипт `oauth_client.py`, который:  
   - Создаёт OAuth-сессию с использованием `OAuth2Session`.  
   - Формирует URL для авторизации пользователя.  
   - После подтверждения доступа пользователем обменивает authorization code на access token.  
   - Использует полученный токен для запроса защищённого ресурса (информации о пользователе GitHub).  

**Результат:** Успешно получен access token и данные пользователя через API GitHub.

### Задание 2: Обновление токена (refresh token)  
Изучена возможность использования refresh token для обновления access token без повторной авторизации пользователя. На примере Google APIs рассмотрен механизм получения и использования refresh token в Python-скрипте.

## Ответы на контрольные вопросы  

1. **Основные роли в OAuth 2.0:**  
   - Resource Owner — владелец ресурса (пользователь).  
   - Client — приложение, запрашивающее доступ.  
   - Authorization Server — сервер, выдающий токены.  
   - Resource Server — сервер, хранящий защищённые ресурсы.  

2. **Authorization Code** — временный код, который клиент обменивает на access token. Позволяет избежать передачи токена через браузер.  

3. **Параметр state** защищает от CSRF-атак, обеспечивая соответствие между запросом и ответом.  

4. **Authorization Code Flow** используется для веб-приложений с участием пользователя, а **Client Credentials Flow** — для сервер-серверного взаимодействия без пользователя.  

5. **Refresh token** используется для получения нового access token без повторной авторизации пользователя, повышая безопасность и удобство.
