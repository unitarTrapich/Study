
# Практическая работа 3 RabbitMQ
Краткий отчет

**Тема:** Разработка распределенной системы агрегации прогнозов погоды с использованием Spring Boot и RabbitMQ  

## Цель работы  
Получение практических навыков разработки распределенных микросервисных систем с использованием RabbitMQ и реализация паттернов интеграции (Enterprise Integration Patterns).  

## Основные задачи  
- Изучить асинхронный обмен сообщениями и паттерны интеграции.  
- Настроить окружение (Java, Maven, Docker).  
- Разработать 4 микросервиса на Spring Boot.  
- Реализовать взаимодействие через RabbitMQ.  
- Внедрить паттерн **Aggregator** для сбора данных.  
- Создать веб-интерфейс для взаимодействия.  
- Протестировать и отладить систему.  

## Используемые технологии  
- Java 17+  
- Spring Boot 3.2.0  
- RabbitMQ (через Spring AMQP)  
- Maven 3.6+  
- Docker  
- OpenWeatherMap API  
- HTML/CSS/JS  

## Архитектура системы  
Система состоит из четырёх сервисов:  

1. **Weather API Service** – принимает HTTP-запросы, разбивает на задачи, отправляет в RabbitMQ.  
2. **Weather Consumer Service** – получает задачи из очереди, запрашивает данные у OpenWeatherMap.  
3. **Weather Aggregator Service** – агрегирует ответы по Correlation ID, формирует отчёт.  
4. **Weather Frontend** – простой веб-интерфейс для ввода городов и отображения результатов.  

## Поток данных  
1. Пользователь вводит список городов → запрос к `Weather API Service`.  
2. API Service генерирует `correlationId`, отправляет сообщения в очередь `weather.request.queue`.  
3. Consumer Service получает сообщения, запрашивает погоду у OpenWeatherMap.  
4. Ответы отправляются в очередь `weather.response.queue`.  
5. Aggregator Service собирает все ответы по `correlationId`, формирует отчёт.  
6. Отчёт отправляется в очередь `weather.aggregated.queue`.  
7. API Service получает отчёт и возвращает его пользователю.  

## Реализованные паттерны EIP  
- **Message Channel** (очереди RabbitMQ)  
- **Message Router** (разделение запроса на города)  
- **Request-Reply** (с использованием Correlation ID)  
- **Aggregator** (сбор ответов, таймаут, стратегия завершения)  

## Результаты  
- Успешно настроено окружение и запущен RabbitMQ в Docker.  
- Реализованы все четыре микросервиса с асинхронным взаимодействием.  
- Создан простой фронтенд для взаимодействия с системой.  
- Система корректно агрегирует данные и возвращает сводный прогноз погоды.  

## Выводы  
В ходе работы были освоены ключевые принципы построения распределенных систем, асинхронной коммуникации через брокер сообщений и применение интеграционных паттернов. Система демонстрирует слабую связанность, отказоустойчивость и возможность масштабирования.  

## Контрольные вопросы (кратко)  
1. **Брокер сообщений** уменьшает связанность и повышает надёжность.  
2. **Correlation ID** связывает запросы и ответы в асинхронной среде.  
3. **Completion Strategy** – счётчик ожидаемых сообщений.  
4. **Ручное подтверждение** гарантирует обработку сообщений.  
5. **Ошибки API** обрабатываются, сообщения не теряются.  
6. **CleanupExpiredAggregations** удаляет “зависшие” агрегации по таймауту.
